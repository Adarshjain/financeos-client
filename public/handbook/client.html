Section 7

07Client / frontend deep dive

Executive summary

A Next.js 16 App Router application (React 19, TypeScript) that renders every authenticated screen twice on purpose: a Server Component page.tsx makes the first API calls and seeds a per-request TanStack Query cache, then a client component hydrates that cache and owns all later reads and writes through browser fetch. The app began as pure Server Components plus Server Actions (the README still describes that design) and was migrated module by module onto TanStack Query in September 2026 while keeping the RSC first paint. Confirmed

Two API layers are both live: lib/apiClient.ts (server-only, 1,349 lines of per-domain wrappers) for RSC prefetch, and lib/api/client.ts (browser openapi-fetch) for interactivity. Three refresh mechanisms coexist. List filters live in component state, not URLs, except the jobs history page. Chat transcripts live only in React state.

Performance notes

  • recharts (~390 KB chunk) is dynamically imported for reports (ReportDataView.tsx:27-47) but statically imported on /investments via HoldingCard → HoldingDetailDialog → PriceHistoryPanel. Confirmed
  • react-grid-layout is never code-split; every dashboard route pays for it.
  • RSC fan-out is parallel everywhere (Promise.all): transactions 3 calls, dividends 4, llm-keys 5, most lists 1.
  • After 30 s away, window focus refetches every mounted query at once.
  • 67% of .tsx files are client components; no bundle analyzer is configured.

Dead code and stale documentation

  • components/layout/AppShellNav.tsx and the needsReviewCount nav path: zero importers.
  • components/transactions/useTransactionWorkspace.ts: zero importers; misleading twin of the live hook.
  • Module-level dead components found by other analysts: DeleteAccount.tsx, dialogs/InstrumentDialog.tsx, dialogs/DividendDialog.tsx, most of GmailSyncResultDetails.tsx.
  • README claims Next 14, middleware.ts, Node 18+, non-existent action files, "no client aggregation", and default credentials. All stale. Confirmed
  • .husky/pre-commit runs only lint:fix; typecheck, tests and build run only in CI.
