11End-to-end user journeys and critical paths

Executive summary

The workflows that explain most of the system, each with its sequence, the code involved and failure points. The seven critical paths at the end are the ones whose failure produces wrong financial information or blocks the product. Confirmed

Journey 1: Open the app and reach the dashboard

Failure points: invalid cookie (one extra hop), API down (error.tsx, not login), widget report broken (only that widget shows unavailable). Code: proxy.ts, lib/auth.ts, actions/auth.ts, AuthService, dashboard/page.tsx, lib/dashboards.server.ts.

Journey 2: Record a manual transaction

  1. intentLog a cash expense on a bank account with a category
  2. UI/transactions → New → TransactionCRUD (signed amount input, account, optional card, categories, flags, reward details); on description blur useCategorySuggestions calls POST /categorize
  3. clientuseTransactionCRUD.handleSubmit → buildTransactionRequest → api.POST('/api/v1/transactions')
  4. serverTransactionService.createTransaction: non-zero, account owned, card belongs to account, sign → type + abs, source manual, review NA, categories resolved, save, AuditLogger CREATE
  5. DBinsert transactions (+ transaction_categories)
  6. responseTransactionResponse re-signed
  7. UIinvalidate transactions.all and accounts.all; list refetches with new running balances
  8. failureZero amount → 400 toast; foreign account → 400 with a security log; double click guarded by isSubmitting only

Code: gmail/ingest/*, domain/job/*, domain/categorization/*, components/transactions/review-browser/*.

Journey 4: Upload a statement

  1. UI/settings/ingest: pick a bank or card account, drop PDFs (≤25 MB client cap), submit
  2. clientBrowser multipart POST /accounts/{id}/ingest via the rewrite (no server action) → 202 {jobId}; emitJobStarted; poll every 1.5 s
  3. serverFileUploadController stages bytes as job_artifacts, enqueues STATEMENT_INGEST, pokes the worker
  4. jobFileIngestionService.ingest: per file parse (password from account) → dedup statement → build rows → dedup transactions (same day, exact, Jaccard ≥ 0.70 → flag) → categorize outside a transaction → save in one write transaction
  5. resultJob SUCCEEDED with per-file status, created and duplicate counts (details capped at 50)
  6. UIIngestionResultDetails renders; transactions.all invalidated
  7. failureWrong password → that file FAILED; exception in the batch phase → whole job FAILED and nothing saved; verdict REJECTED still ingests

Journey 5: Configure a card's rewards and check what it earned

  1. UI/rewards/rules: pick the account, add rules (match, earn, limits sections), buckets, milestones; reorder; set anniversary in the account form and point value in config
  2. serverRewardRuleService.create validates predicates, tiers, caps, bucket type; saves; keys.rewards.all invalidated
  3. UI/rewards: pick account and range → useRewardReport and useRewardLines
  4. serverRewardCalculationService.report: window expansion, fetch, evaluate every transaction, aggregate
  5. UISummary cards, rule breakdown with cap status, milestone progress, lines with reasons
  6. decision/rewards/recommend: enter a hypothetical spend → ranked cards with guaranteed and milestone value
  7. failureRange too large for milestones → 400; broken tier JSON → rule skipped silently; no statements → cycle fallback flag

Journey 6: Import a broker year and see positions

  1. UI/investments/tradebook → Import Wizard → mode reconcile_zerodha, broker account, tradebook CSVs + tax P&L XLSX
  2. previewPOST /imports/reconcile/preview (sync): dedup executions, classify intraday per day, split rows, delivery FIFO, warnings, derived holdings, unmatched instruments
  3. reviewStep 2: resolve instruments (or Create new), uncheck rows
  4. commitPOST /reconcile/commit → 202 job → writes trades (source import, charges verbatim), classifications (insert-if-absent), F&O trades; price refresh event
  5. UIStep 3 counts; invalidate investments.all and accounts.all; /investments recomputes positions by FIFO with classifications
  6. later19:00 IST price refresh updates values; corporate actions recorded manually replay on read
  7. failureMissing tax P&L → everything delivery; duplicate commit → service dedup (race possible); corrected classifications cannot overwrite

Journey 7: Track a loan

/loans → New (terms) → schedule computed to validate → /loans/[id] shows hero and schedule → record events (rate change, prepayment) → Find Matches → Confirm → payments recorded → calendar shows upcoming EMIs → tax report via reports datasource. Failure points: non-amortizing EMI (400), prepayment ≥ outstanding (400), payment without seq retried (settles the next installment). Code: domain/loan/*, app/(protected)/loans/**.

Journey 8: Ask a question and save a report from the answer

/chat → question → SSE status and trace events → answer with blocks → a report draft card previews via runAdHocReport → user clicks Save → createReport action → report appears in /reports. Failure points: quota 30/day, 2 concurrent, no keys, deadline. Code: chat/**, app/api/chat/route.ts, app/(protected)/chat/**.

Journey 9: Delete the account

/settings → type DELETE and password → limiter → re-auth → drain jobs (5 s) → revoke Google tokens → delete user with dictionary verification → destroy sessions → /login?deleted=1. See §15.
