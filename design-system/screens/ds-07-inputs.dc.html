Inputs

Each component with its rules, rendered in the light and the dark theme.

TextField
Inputs

A labelled text input. Labels sit above the field in `ink-2`, 12px bold; helper or error text sits below.

States

Default, filled, placeholder (ink-4), focus (2px focus-ring), error (danger border and message that says how to fix it), locked (bg-sunken, lock icon, no explanation needed: e.g. the account of an imported transaction).

Rules

  • Dates are typed and shown as dd/mm/yyyy.
  • Amounts are right-aligned only in tables; in forms they read left to right with a ₹ prefix.
  • Optional fields say "(Optional)" in the label: "MCC Code (Optional)".
  • Secrets (statement passwords) are masked with a show toggle.

Variants

  • States: default, placeholder, focused, with helper, error (red border and a message that says how to fix it), disabled, locked (lock icon, no explanation).
  • Kinds: amount with a ₹ prefix, password with Show, date (dd/mm/yyyy with a calendar icon), multi-line note, read-only value as a label/value row.

Select
Inputs

Single-choice fields are always a dropdown, never tiles or chip groups. Multi-choice fields are a multi-select dropdown with the chosen values as chips inside the field.

Use

  • Closed: looks like a text field with a ▾ caret; the value may lead with an icon (bank logo).
  • Open: a Menu with search when long, ✓ on the current value; on phone it opens as a bottom sheet.
  • Multi-select shows chips inside the field and wraps to a second line before it truncates.
  • Dependent fields appear only after their trigger: "Why it needs review" appears when Review status is Needs review.

Don't

  • Don't use radio tiles or segmented chips for single choice in forms (the only exception is the four account-type buttons at the top of Add account).
  • Don't offer an "Other" option to escape a list; add search instead.

Variants

  • Single select: ✓ on the current value; picking closes the list.
  • Single with search and icons: search first when there are more than about eight options; icons lead (bank logos).
  • Multi select: square checkboxes, Clear and "Done · n" at the bottom; the field shows the picks as chips and "+n" when they overflow.
  • Multi with search: typing filters; "Create "…"" appears when nothing matches and creating is allowed (categories).
  • Sectioned list: uppercase group headers (Bank accounts · Credit cards · Wallets & cash).
  • With an action row: a separator and a brand-coloured action at the end ("+ New shared limit…").
  • Search · create from typing: matches first, then "+ Add "…"" (counterparties).
  • No results: one line that repeats what was typed.
  • With descriptions: a second line under each option; radio marks when the choice needs explaining.
  • Disabled option: greyed with the reason as a hint.
  • Closed field states: value, placeholder, icon, focused, chips, overflow, error, disabled, locked, loading.

SearchField
Inputs

A search box with a leading magnifier. Every search input carries the icon.

Use

  • In lists it is the first thing in the filter area. On phone it takes its own full-width row above the filter chips.
  • Inside sheets it is a labelled field ("Find the other side") so it reads as an input, not a filter.
  • Placeholder names what can be searched: "Search merchant keys or names…".

Variants

  • Empty, typing with a clear ×, labelled inside a sheet, no results.

FilterChip
Inputs

Filter chips sit in one scrolling row under the search. They filter the list in place and combine with AND.

Variants

  • Default: outlined, ink-2 text, optional ▾ when it opens a picker.
  • On: brand-tint with brand-border and brand-strong text.
  • Review: the "Needs review · 25" chip turns amber (chip-amber) when on, since it shows what needs you.
  • A chip that opens a picker shows its value when set: "Account · 2".

Use

  • Status chips first (Unverified · Verified · All), then Category, then the rest.
  • The row never wraps; on phone it scrolls and bleeds to the edges.
  • Toggles that the user did not set stay off by default ("Up to statement").

Variants

  • Off, on, on with a value, with a count, removable, review (amber when on), plain toggle, and the dashed "+ More" that opens the full filter sheet.

Switch
Inputs

A switch for a setting that takes effect on save, shown as a toggle row: label and optional explanation on the left, switch on the right.

Use

  • On is brand, off is line-handle; always pair it with a text label.
  • In forms the row sits inside its section band group; the explanation is caption in ink-3.

Don't

  • Don't use a switch for a choice between two named options; use a Select.

Variants

  • Off, on, disabled (both), and the toggle row with a label and an explanation.

SegmentedControl
Inputs

Two to four mutually exclusive views of the same content, shown side by side: Debit | Credit, List | Calendar.

Use

  • The active segment is ink fill with bg-surface text.
  • Use it for switching how something is shown, or for a two-way choice at the top of a form. Field-level single choices are Selects.

Variants

  • Two or three options; used for a view switch or a mode at the top of a form.

DropZone
Inputs

The import area: drop files or choose them, then each queued file is a row with its name, size and a trash icon.

Use

  • Centred stack: icon tile, "Add statements", one line of what is accepted, then the Choose files button (phone label "Choose files").
  • Queued files show name, size and remove only. The user picks the account; nothing is detected or asked for at upload time.
  • Recent imports below are rows with the file name and a coloured status word ("Done" in positive, "1 warning" in warning), no icons.

Variants

  • Idle, dragging over, queued files (name, size, remove), and a file that cannot be sent.
