Navigation

Each component with its rules, rendered in the light and the dark theme.

AppBar
Navigation

The phone app bar: the brand mark (or a back arrow on detail screens), breadcrumb and screen title, then Ask the data, Search and the one + (`brand` fill) that adds whatever the screen is about.

Use

  • Every phone screen has exactly one. It replaces a body title: phone pages never repeat the title as an H1.
  • The + is page-aware: on Transactions it opens Quick add, on Rules it opens New rule, on Accounts it opens Add account. Never add a second "New …" button in the page header.
  • Detail screens swap the mark for a back arrow (back).

Consumer provides

crumb (section path, optional), title, back (boolean), the add target for the +.

Don't

  • Don't put page actions (Export, Merge…) here; they live in the page or in a ⋮ menu.
  • Don't wrap the title; it truncates with an ellipsis.

TabBar
Navigation

The phone tab bar: Home · Inbox · Upcoming · Transactions · More, always in that order.

Use

  • Shown on every top-level phone screen; hidden while a list is in selection mode (the selection bar takes the bottom edge) and under the keyboard.
  • Count bubbles: danger for things that need you now (Inbox), warning for the review count on Transactions. Over 99 shows "99+".
  • The active tab uses brand-strong for icon and label. Icons are 20px Lucide-style strokes, labels use tab-label.

Don't

  • Don't add a sixth tab or reorder; new sections go under More.
  • Don't use a count bubble for information that needs no action.

Tabs
Navigation

A tab strip that switches between sibling views of one section (All · Rules · Categories · Import).

Use

  • Tabs never wrap: on phone the strip scrolls sideways and bleeds to the screen edges.
  • Put counts in the label only when they help decide where to go ("Tradebook · 38").
  • The active tab is brand-strong text with a 2px brand underline.

Don't

  • Don't use tabs for filters on the same data; that is what filter chips are for.
  • Don't put a Settings tab on an object page; settings belong in its edit sheet.

Variants

  • Plain, with counts, and scrolling (never wrapping) when they overflow on phone.

Pager
Navigation

Pagination for any list that can outgrow one page, matching the app's TablePagination: the visible range out of the total, rows per page, and numbered pages with first, last and neighbours.

Use

  • It sits above and below the list: the first row of the list's card (under the card header, above the table header) and its last row. Card-grid lists (rule cards) put it above and under the grid. Both copies always show the same page.
  • Desktop: "1–50 of 182 transactions" · "50 / page ▾" · ‹ 1 2 … 4 ›.
  • Phone: drop the unit and the page-size select, keep one neighbour fewer: "1–50 of 182" · ‹ 1 … 4 ›.
  • A single page shows the count and page size only, no arrows.
  • Server-side paging only. Never load every row and slice on the client.

Consumer provides

page (0-based), size, totalElements, totalPages, unit (singular noun), onPageChange, onSizeChange.

Don't

  • Don't use "Load more" or infinite scroll for money lists; people need to say "page 3" and come back to it.
  • Don't show two pagers on one list.
