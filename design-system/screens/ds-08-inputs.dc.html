Inputs

Each component with its rules, rendered in the light and the dark theme.

TextField
Inputs

A labelled single-line input. Label above in `ink-2` 12px bold; helper or error below.

Kinds

  • Text, number, email.
  • Amount: ₹ prefix, reads left to right in forms (right-aligned only in tables).
  • Password: masked with a Show toggle (statement passwords).

States

Default, filled, placeholder (ink-4), focus (2px focus-ring), error (danger border and a message that says how to fix it), disabled.

Not here

  • Dates: DateField. Multi-line: TextArea. A read-only value: ListField (label/value row in ListRow). No locked state: a field that can't change is disabled.
  • Optional fields say "(Optional)" in the label.

Built from

The shared field frame (label, helper, error) that TextArea, DateField and Select also use; Icon (password toggle).

Variants

  • Kinds text, amount, password; states default, placeholder, focused, with helper, error, disabled.

TextArea
Inputs

A labelled multi-line field for notes and descriptions.

Use

  • Same label, helper and error as TextField; 3 rows tall by default (rows={3}), grows with content up to 8 rows, then scrolls.
  • No character counter unless the server enforces a limit.

The shared field frame (label, helper, error) that TextField uses.

DateField
Inputs

The only date input. Shows and accepts dd/mm/yyyy, with a calendar in a Popover for picking.

Use

  • Typing: digits only, slashes added as you type (13102026 → 13/10/2026). Invalid dates show an error that says the format.
  • Calendar: the calendar icon at the right opens a Popover with MonthCalendar; Today and Clear in its footer. On phone the calendar opens in a Dialog (bottom sheet).
  • Range mode: two typed fields ("From", "To") sharing one calendar; the range shows as a brand-tint band.
  • Never <input type="date">.

Built from

TextField's field frame, Popover, Dialog (phone), MonthCalendar (from DateTile), Icon, Button.

Variants

  • Single date, date range, with min/max (days outside are greyed), error, disabled.

Select
Inputs

The dropdown for choosing values. Single-choice fields are always a Select, never tiles or chip groups; multi-choice fields are a multi-select with the picks as chips inside the field.

Use

  • Closed: a field with the value (optionally led by an icon or image, such as a bank logo) and a ChevronDown (icon-md) at the right that turns to ChevronUp while open.
  • Open: a Popover exactly as wide as the trigger, with search first when there are more than about eight options and a Check on the current value. On phone the list opens in a Dialog (bottom sheet) instead.
  • Custom trigger: any element can open the list through the trigger slot. A FilterChip is the trigger for every dropdown filter, so filter chips get search, multi-select, sections and the phone sheet for free. One dropdown, never a second chip-only dropdown.
  • Multi-select chips wrap to a second line before they truncate; "+n" when they overflow.
  • Dependent fields appear only after their trigger.

Don't

  • No locked state: a field that can't change is disabled.
  • Don't use radio tiles or segmented chips for single choice in forms (the four account-type buttons on Add account are the only exception).
  • Don't offer an "Other" option to escape a list; add search instead.

Built from

Popover, Dialog (phone), SearchField, Checkbox (multi), CategoryChip (chips in the field), Icon, Button (Clear, Done).

Variants

  • Single select; single with search and icons (icons may be images); multi select (checkboxes, Clear and "Done · n"); multi with search and "Create "…""; sectioned list; with an action row ("+ New shared limit…"); search · create from typing; no results; with descriptions; disabled option; custom trigger (FilterChip).
  • Closed field states: value, placeholder, icon, open, chips, overflow, error, disabled, loading.

SearchField
Inputs

A search box with a leading magnifier. Every search input carries the icon.

Use

  • In lists it is the first thing in the filter area. On phone it takes its own full-width row above the filter chips.
  • Inside sheets it is a labelled field ("Find the other side") so it reads as an input, not a filter.
  • Placeholder names what can be searched: "Search merchant keys or names…".

The shared field frame, Icon.

FilterChip
Inputs

A chip in the filter row under the search. Chips filter the list in place and combine with AND. FilterChip only draws the chip; a chip that opens choices is the `trigger` of a Select, so the list, search, multi-select and phone sheet are the Select's.

Looks

  • Off: outlined, ink-2 text. On: brand-tint, brand-border, brand-strong text. Review: amber when on ("Needs review · 25").
  • A dropdown chip shows a ChevronDown and, once set, its value: "Account · 2".
  • Removable chips end in an X. The chevron and the X are both icon-sm (14px), in the same colour as the label.
  • With a count: a CountBubble after the label.
  • "+ More": dashed, opens the full filter Dialog.

Use

  • Status chips first (Unverified · Verified · All), then Category, then the rest. The row never wraps; on phone it scrolls and bleeds to the edges.
  • Toggles the user did not set stay off ("Up to statement").

Built from

Icon, Badge (count). Dropdown chips: Select with trigger={<FilterChip …/>}.

Variants

  • Off, on, on with a value, dropdown, with a count, removable, review (amber), toggle, "+ More".

Checkbox
Inputs

A square tick box for multi-choice on desktop: the selection column of desktop tables, multi-select options, and confirm lists ("Select all 12 matches").

Use

  • 16px box, radius-xs, 2px line-strong border; on = brand fill with a white Check (icon-sm).
  • Mixed (some rows selected) shows a dash.
  • Phone selection never shows checkboxes (RULES §7.4); rows tint and stripe instead.

Radix Checkbox, Icon.

  • Off, on, mixed, disabled.

Switch
Inputs

A switch for a setting that takes effect on save, shown as a toggle row: label and optional explanation on the left, switch on the right.

Use

  • On is brand, off is line-handle; always pair it with a text label.
  • In forms the row sits inside its section band group; the explanation is caption in ink-3.

Don't

  • Don't use a switch for a choice between two named options; use a Select.

Built from

Nothing else (a button with role="switch").

  • Off, on, disabled (both), and the toggle row with a label and an explanation.

SegmentedControl
Inputs

Two to four mutually exclusive views of the same content, shown side by side: Debit | Credit, List | Calendar.

Use

  • The active segment is ink fill with bg-surface text.
  • Use it for switching how something is shown, or for a two-way choice at the top of a form. Field-level single choices are Selects.

DropZone
Inputs

The import area. The whole zone is the target: tapping or clicking anywhere in it opens the file picker, and dropping files anywhere on it adds them, in every state, including while files are queued.

Use

  • Centred stack: icon tile, "Add statements", one line of what is accepted, and the Choose files button (a visible cue; the zone itself is the control).
  • Dragging over: brand dashed border on brand-tint.
  • Queued files show name, size and remove only. The user picks the account; nothing is detected or asked for at upload time.
  • A file that can't be sent says why in words ("Larger than 10 MB"), not only in red.
  • Recent imports below are rows with the file name and a coloured status word ("Done" in positive, "1 warning" in warning).

Built from

Button, ListRow (queued files), Icon, StatusWords.

Variants

  • Idle, dragging over, queued files, a file that cannot be sent.
