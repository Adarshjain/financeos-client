Actions

Each component with its rules, rendered in the light and the dark theme.

Button
Actions

Buttons: one primary per view, secondary for everything else, ghost for low-emphasis icon actions, danger for destructive ones.

Variants

  • btn secondary (default): bg-surface with a line-strong border.
  • btn-p primary: brand fill, on-brand text. One per screen or sheet: "Save", "Save & apply", "Approve 2 rules".
  • btn-d danger: danger text and danger-border. Starts a destructive action; always followed by a confirm step.
  • btn-dd danger filled: danger fill. Only the final button of a ConfirmDialog ("Delete statement").
  • btn-g ghost: no border; icon actions in bars and cards.
  • btn-i square icon button; give it an aria-label.
  • Sizes: btn-s 26px inside rows and card headers (desktop), default 32px, btn-xl 44px for phone sheet footers and auth.

Copy

Name the action with a verb and its object: "Mark paid", "Upload statement", "Approve 9". Never "OK" or "Submit".

Don't

  • Don't put a create button ("New category") in a page header; the + in the app bar does that.
  • Don't put two primary buttons side by side.
  • Phone tap targets are at least 44px tall in sheets; 32px is fine inside dense rows.

Built from

Icon, Badge (count), Radix Slot (asChild for links).

Variants

  • Variants: primary, secondary, danger outline (starts a destructive action), danger filled (final confirm), ghost.
  • Sizes: small 26 (rows, card headers), default 32, phone 44 (sheet footers, auth).
  • States: default, hover, focus ring, loading (label changes to the ongoing verb), disabled.
  • Icon-only buttons always carry an aria-label; counts sit in a dark pill after the label.

Menu
Actions

A list of **actions** that opens from a trigger: the ⋮ menu on a rule or account, the dashboard ⋯ menu, snooze presets.

Menu vs Select

Both open the same Popover with the same item rows, so they look identical. They differ in what they mean: a Select holds a value (it shows the current pick, is part of a form, and has search, multi-select and create); a Menu runs a command and keeps no value (items can be destructive, it closes and something happens). Radix, Material, Polaris and Atlassian all keep the two apart for this reason. Here they share the Popover and the item row, so nothing is drawn twice.

Use

  • Verbs, most common first, destructive last after a separator in danger.
  • Optional right-aligned hint in ink-4 ("Tomorrow · Wed 14 Oct"); hidden on phone.
  • On phone, menus with more than about six items open as a Dialog (bottom sheet).
  • Arrow keys move, Enter runs, Escape closes.

Don't

  • Don't put a single action in a menu; show it as a button.

Built from

Popover (Radix DropdownMenu), the shared item row, Icon, Dialog (phone, long menus).

Variants

  • Actions; with icons and hints (icons only when every item has one); snooze presets with "Pick a date…"; disabled item with its reason; sectioned; switcher with a footer link.

SelectionBar
Actions

The bar that appears while items are selected: the count, a one-line summary, and the actions that apply to the selection.

Use

  • Phone: docked to the bottom edge like a sheet (bulk dock), tab bar hidden. Top row: × to finish, "2 selected" with a summary, "Select all N". Below: up to four icon actions with a small hint each.
  • Desktop: a floating pill centred above the list with outlined actions and × at the end (Esc also clears).
  • Actions that do nothing for some of the selection still run for the rest and say so: "Approve 9" approves only the ones that need it.
  • Same component everywhere: transactions (Link · Merge · Approve · Delete) and rules (Approve).

Selection model (phone)

Long-press a row to start, tap to add or remove, the eye icon opens the item's detail without leaving selection, × or back to finish. No checkboxes on phone. Desktop uses checkboxes.

Built from

Button, Icon.

Variants

  • Four actions (transactions), a single action (rules), and an action that does not apply to the current selection (greyed, with the reason in the subtitle).

SwipeActions
Actions

A phone row gesture. It wraps any row and reveals what each side will do while the finger moves; when the swipe passes the threshold it calls the handler the page gave it and springs back. It never confirms, deletes or opens anything itself.

Props

  • left and right, each optional: { label, icon, tone, onTrigger }. Omit a side to make the row swipe one way only; pass the same action to both sides if both should do it.
  • disabled for rows that can't swipe.

How pages use it

  • Transactions: right Approve (brand), left Delete (danger). The page shows its ConfirmDialog for Delete; Approve applies at once with an Undo Toast (RULES §5.7).
  • Inbox: right Snooze until tomorrow, left Dismiss; both apply at once with Undo.
  • The background under the row shows the side's icon and one-word label in its tone; past the threshold (40% of the row, or a fast flick) it fires once.

Rules

  • No tap action of its own: a tap goes to the row.
  • Vertical scrolling wins until the finger moves sideways (touch-action: pan-y).
  • Every swipe action is also reachable from the row's detail; gestures are shortcuts.

Built from

A shared useSwipe hook (pointer tracking, threshold, spring back) and Icon. The row inside is the page's (TransactionRow, ListRow).

Variants

  • Both sides; right only; left only; disabled.
