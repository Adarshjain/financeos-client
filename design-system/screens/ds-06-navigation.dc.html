Navigation

Each component with its rules, rendered in the light and the dark theme.

TopBar
Navigation

The bar at the top of every screen: one component, two forms chosen by CSS at the `lg` breakpoint (like Dialog). On phone it is the TopBar; on desktop it is the page bar above the content. Pages never choose.

Forms

  • Phone (56px, app-bar): the Logo mark, or a back arrow on detail screens (back), then crumb and title (title truncates, never wraps), then the actions as bordered control-md icon buttons. Phone pages never repeat the title in the body.
  • Desktop (56px, bg-surface, line bottom border): crumb and title on the left, the actions on the right; an action with a label shows it ("Add" with its ⌘N hint).

Props

  • title, optional crumb, optional back (href or handler).
  • actions: an ordered list the app passes in, each { id, icon, label, href | onSelect, variant?: 'default' | 'primary', shortcut? }. The bar renders them; it decides nothing about which ones exist. FinanceOS passes Ask the data, Search and the + (primary) on phone, and Add (⌘N), Chat and Notifications on desktop.

Rules

  • The + (primary) opens the add form for the current screen; it is the only add button (RULES §7.1).
  • Page actions (Export, Merge…) don't go here; they live in the page or a ⋮ menu.

Built from

Logo, Button, Icon, Kbd.

Variants

  • Top level, detail (back + crumb), with a primary action, phone and desktop forms.

TabBar
Navigation

The phone bottom navigation. It draws the items the app gives it, in the order given; FinanceOS passes Home · Inbox · Upcoming · Transactions · More.

Use

  • Shown on every top-level phone screen; hidden while a list is in selection mode (the selection bar takes the bottom edge) and under the keyboard.
  • Count bubbles: danger for things that need you now (Inbox), warning for the review count on Transactions. Over 99 shows "99+".
  • The active tab uses brand-strong for icon and label. Icons are lg (20px) from the registry, labels use tab-label.

Don't

  • Don't add a sixth tab or reorder; new sections go under More.
  • Don't use a count bubble for information that needs no action.

Props

  • items: { id, label, icon, href, count?, countTone?: 'danger' | 'warning' }[] (at most 5), and current (the id of the current item). No item, label, route or count is built into the component.

Built from

Icon, Badge (count). Items are links with the current one marked.

Rail
Navigation

The desktop left navigation, 240px (`rail`). Phone uses TabBar and More instead.

Anatomy

Brand row (₹ mark + FinanceOS), the search button with its ⌘K hint, Home · Inbox · Upcoming, then grouped sections with overline headers (Money · Grow · Owe & lend · Insights), and Settings with the account avatar pinned at the bottom.

Use

  • The current page is brand-tint with brand-strong text and icon.
  • Counts: Inbox uses a danger CountBubble (needs you now); Transactions shows the review count as a warning number, no bubble.
  • Items are links (href), icons lg, labels body-strong.

Props

groups: { label?, items: { id, label, icon, href, count?, countTone? }[] }[], current, search (handler and shortcut), footer items (Settings) and user (name, avatar): all from the app. The component has no default items, labels or routes.

Built from

Icon, Badge (count), Avatar, Kbd, Button (search).

Variants

  • Default, with counts, collapsed group headers hidden when a group has one item.

Tabs
Navigation

A tab strip that switches between sibling views of one section (All · Rules · Categories · Import).

Use

  • Tabs never wrap: on phone the strip scrolls sideways and bleeds to the screen edges.
  • Put counts in the label only when they help decide where to go ("Tradebook · 38").
  • The active tab is brand-strong text with a 2px brand underline.

Don't

  • Don't use tabs for filters on the same data; that is what filter chips are for.
  • Don't put a Settings tab on an object page; settings belong in its edit sheet.

Underline

  • The current tab's underline is a straight 2px brand bar the full width of the label: square ends, no radius. The tab itself has no rounded corners.

Built from

Radix Tabs; the count after a label is ink-3 text, not a bubble.

Variants

  • Plain, with counts, and scrolling (never wrapping) when they overflow on phone.

Pager
Navigation

Pagination for any list that can outgrow one page, matching the app's TablePagination: the visible range out of the total, rows per page, and numbered pages with first, last and neighbours.

Use

  • It sits above and below the list: the first row of the list's card (under the card header, above the table header) and its last row. Card-grid lists (rule cards) put it above and under the grid. Both copies always show the same page.
  • Desktop: "1–50 of 182 transactions" · "50 / page ▾" · ‹ 1 2 … 4 ›.
  • Phone: drop the unit and the page-size select, keep one neighbour fewer: "1–50 of 182" · ‹ 1 … 4 ›.
  • A single page shows the count and page size only, no arrows.
  • Server-side paging only. Never load every row and slice on the client.

Consumer provides

page (0-based), size, totalElements, totalPages, unit (singular noun), onPageChange, onSizeChange.

Don't

  • Don't use "Load more" or infinite scroll for money lists; people need to say "page 3" and come back to it.
  • Don't show two pagers on one list.

Built from

Button, Icon, Select (rows per page).
